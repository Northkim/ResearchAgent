## Change packet

### 1. Objective

Add the smallest Owner-managed GitHub Agent Skill library, explicit Project
attachment, and normal Workspace-sync installation into `.agents/skills/`.

### 2. Owner intent and user problem

An Owner should record reusable Agent instructions once, attach them to Projects,
and let the existing `python reagent_local.py sync .` reconcile them. ReAgent
coordinates identity, association, provenance, and managed local presence. The
Agent Harness discovers and uses installed Skills; ReAgent never executes them.

### 3. Current baseline and authority

- ADR 0033 makes `local_builtin_skill_definitions`, immutable Skill Versions, and
  Workflow pins reviewed publication authority delivered inside Capsules.
- Existing `reagent.workspace-installed-lock/v0.1` already reserves the
  `installed_skills` collection, but current validation requires it to be empty.
- Current sync owns Capsule installation and acknowledgement; there is no separate
  Skill command.
- The current Full Research product is accepted at EP-D2; D1 is paused with five
  Workflow Instances and no Progress, Artifact, or binding rows.
- The Owner prompt explicitly authorizes a distinct user-managed Skill slice and
  supersedes the older deferral of imported/private Skills only within this scope.

### 4. Source decisions and conflicts

- `USER_SKILL_STORAGE = MINIMAL_NEW_USER_SKILL_MODEL`.
- `LOCAL_SKILL_SYNC = MINIMAL_EXTENSION_REQUIRED`.
- Reviewed Skill publication is immutable and semantically unsuitable: it requires
  built-in/reviewed trust, versions, Workflow pins, and Capsule checksum delivery.
- No blocking source conflict remains because user-managed Skills use separate
  records, do not enter reviewed publication, and do not satisfy Capability trust.

### 5. Scope

- Minimal `UserSkill` and `ProjectUserSkill` persistence.
- Exact GitHub source parsing, bounded resolution, `SKILL.md` validation, and exact
  resolved revision/package checksum provenance.
- List/create/read/safe-delete and Project attach/detach/sync-report API.
- One compact Skills page, global navigation, and small Project Overview section.
- Existing Workspace sync reconciles owned `.agents/skills/<slug>/` directories and
  records them in the existing Installed Lock.

### 6. Non-goals and deferred findings

No marketplace, ratings, review/certification, release history, upload/editor,
OAuth, scheduler, Skill runtime, activation button, hosted execution, Workflow,
Capability promotion, D1 execution, or Full Research change. Structured API error
observability beyond existing coded errors is deferred.

### 7. Domain semantics and transitions

- Create: validated GitHub source -> exact resolved commit and bounded package ->
  UserSkill. Retry is not an implicit duplicate operation.
- Attach: unattached -> attached/Needs sync. Exact repeated attach is idempotent.
- Sync: attached set + exact sources -> staged verified local directories -> lock
  entries -> exact Cloud report -> Ready. Same bytes replay as `NO_CHANGE`.
- Detach: attached -> absent. Exact repeated detach is safe. Next sync removes only
  a matching ReAgent-managed directory.
- Delete: allowed only with zero Project associations; otherwise conflict.
- Source failure or local drift fails closed without overwriting/deleting user-owned
  content. No scientific Workflow state changes.

### 8. Contract, API, persistence, and Artifact impact

- New mutable user records are distinct from immutable reviewed Skill contracts.
- New API is under `/user-skills` and `/projects/{project_id}/user-skills`; the
  existing read-only reviewed `/skills` catalog is unchanged.
- One additive migration creates two tables; existing Projects receive no rows.
- Installed Lock v0.1 accepts its already-reserved `installed_skills` field with a
  bounded exact entry contract; historical empty lists remain valid.
- No Artifact, Workflow, Capsule, Progress, presentation, or Capability contract is
  changed.

### 9. Frontend and safety boundaries

The Skills page shows only name, one-line purpose, usage, and one primary Add action.
Project Overview uses a small secondary section. Source/provenance is collapsed.
Cloud stores locator, resolved revision, checksum, associations, and bounded status,
not package bytes. Local resolution is GitHub-only, bounded, redirect/credential/path
safe, and writes only managed directories. Browser never writes Workspace state.

### 10. Compatibility and migration

This is an additive compatible model plus a compatible interpretation of an
already-present empty Installed Lock field. Migration `20260818_0033` is expected;
no historical migration or publication row changes. Downgrade is allowed only after
removing new user Skill rows and does not affect existing Projects.

### 11. File budget

Expected: at most 12 production/migration files, 4 test/fixture files, and 3
governance files; at most 19 tracked files and 2,200 net lines. Expected areas are
`backend/user_skills.py`, ORM/UoW/composition/router, Workspace CLI, one migration,
four compact frontend surfaces, focused backend/local/frontend/browser tests,
context/progress, and one accepted ADR. Any material expansion stops as
`SKILL_M1_SCOPE_EXPANSION`.

### 12. Rejected alternatives

- Reusing reviewed Skill publication: wrong trust, immutability, and Capsule-pin
  semantics.
- A second Skill sync command/lock: duplicate ownership truth and worse UX.
- Cloud package storage: unnecessary retention.
- Backend Skill execution/Capability promotion: violates the Harness boundary.
- Unmanaged overwrite or name-based deletion: unsafe local ownership.
